# 打包与独立更新

主程序保持“exe + 外置官方插件、桥接和动作”结构。开发源码目录不按安装目录重排；构建与缓存全部进入 build/，发布文件进入 dist/。操作入口见 [build-guide.md](build-guide.md)。

## 文件归属

| 类别 | 目录或文件 | 更新行为 |
|---|---|---|
| 官方程序 | QzTools.exe、QzUpdater.exe、_internal/ | 清单内替换 |
| 官方功能 | plugins/、maya_actions/、max_actions/ | 清单内替换，删除上一清单已废弃文件 |
| 官方桥接 | maya_bridge/、max_bridge/ | 清单内替换，运行中的宿主代码不会凭磁盘替换自动刷新 |
| 官方配置及资源 | defaults.json、version.json、ui/resources/ | 随发布更新 |
| 用户资产 | data/、user_plugins/、temp/、backups/ | 不进入发布包，不被更新覆盖 |
| 更新记录 | updates/ | 保存替换备份、执行结果和锁 |

官方插件的改名和删除入口已取消，用户自定义插件管理不变。既有手工修改过的官方文件在下一次更新时按官方版本替换；更新助手保留旧文件备份。

## 独立助手

QzUpdater.exe 是单独的 onefile 程序，使用自身 Python 和 Tk 运行库，不使用正在替换的中台 Qt 运行库。

中台设置页选择本地更新 ZIP，确认后启动助手的临时副本，保存设置并正常退出。助手等待指定中台 PID 退出，不强杀中台、不关闭 Maya/Max。单独运行助手则需先自行关闭中台。助手临时副本位于系统临时目录，避免根目录 QzUpdater.exe 本身被占用而无法更新。

更新流程：

1. 检查产品、版本、文件清单、路径、大小和 SHA256。
2. 完整解压到安装目录 updates/ 的独立工作目录，校验后才开始修改。
3. 备份本次涉及的旧官方文件；只处理新旧清单覆盖的路径。
4. 替换新增/变更文件，删除已废弃的旧官方文件，最后提交新清单。
5. 在隔离设置目录中运行新版中台 --selftest。
6. 验证通过后重新打开中台；异常则尝试恢复原文件并保留备份和报告。

同一安装目录一次只允许一个更新进程。拒绝更新开发源码目录、路径越界、目录链接、非官方文件和降级包；支持同版本重新安装。旧安装若尚无 release-manifest.json，先完整部署新版，不能直接假设旧目录中的文件归属。

失败信息与备份保存在 updates/install-*/result.json、backup/。正常异常和自检失败支持恢复；强制断电、进程被外部终止、磁盘损坏等不属于已验证的事务恢复范围，保留日志与备份用于人工恢复。校验值用于完整性检查，更新包应来自可信发布位置；本版尚未接入在线下载或发布签名。

## 数据与配置

defaults.json 为官方默认值，data/settings.json 仅保存个人覆盖，递归合并。data/layout.json 保存布局、日志上限、置顶等，data/theme.json 保存主题配色。首次运行复制旧配置，不删除旧 config.json 或 ~/.qz-tool 文件，新文件存在时不再迁移。测试可设置 QZ_DATA_DIR 使用独立目录，禁止从真实用户目录导入数据。

用户脚本继续保存在 user_plugins/maya/ 和 user_plugins/max/。权重文件及交换数据继续使用项目 temp/。更新程序不清理这些目录。

## 生效范围

首版采用一套完整官方更新包，更新后重启中台。现有部分业务实现随中台编译，尚未提供插件界面热更新。

Maya/Max 动作可以通过现有动作库重载更新；桥接核心或协议变更按发布说明重新启动桥接或宿主。不能把“中台重启”视为“DCC 内所有模块已重载”。宿主自动启动及固定按钮仍依赖固定项目路径，更新保持目录位置。

## 构建依据

采用 [PyInstaller 官方构建参数](https://pyinstaller.org/en/stable/usage.html)：主程序 onedir、助手 onefile、specpath/workpath/distpath 独立。助手单独运行可避免在替换中台时锁住其依赖。
