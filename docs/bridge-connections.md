# 桥接连接与断开

设置页“桥接”下分别显示 Maya、3ds Max 和 Blender 的连接状态、版本及操作按钮。地址和端口由 defaults.json 与 data/settings.json 合并配置。

## Blender 5.2 LTS

1. 在 Qz 设置页的 Blender 行点击「连接」，复制单行启动代码。
2. 在 Blender 中打开 Python 控制台，粘贴代码并按回车运行。中台自动发现桥接并显示版本。Blender 默认监听本机 `127.0.0.1:17025`，生成的启动代码使用当前配置的 `bridge.ports.blender`。
3. 从资源树的 Blender 分组打开「读取选择」，点击卡片按钮后在日志中查看所选对象的名称和数量。场景和选择保持原样。
4. 在设置页点击「断开」释放监听端口。重新执行启动代码即可重连。

Blender 沿用协议 3。应用定时器在主线程读取场景，socket 线程用缓存的版本和定时器状态回复心跳。定时器长时间未运行或界面锁定时显示「等待响应」，执行桥接动作期间显示「繁忙」。这两种状态下新的动作和断开请求需要等恢复后重试。每次最多处理一个桥接动作，心跳不排入主线程队列。定时器跨文件加载保留，并在断开后的下一次回调中退出。

读取选择使用定时器上下文中的视图层。若上下文没有视图层，则使用 Blender 窗口列表中第一个窗口的视图层。

资源树的「Blender → 设置」提供 **Ping**、**Reload Plug** 和 **Install to Blender**。Ping 将版本与主线程状态记入日志，Reload Plug 重新扫描 `blender_actions/`。

### 安装和卸载自动启动

先手动连接 Blender，再打开 **Install to Blender** 卡片，点击「安装自动启动」。卡片向当前 Blender 查询用户启动目录，将 Qz 启动脚本 `qz_bridge_startup.py` 写入该目录。下次打开 Blender 界面时会自动启动桥接，使用安装时的端口。修改端口后可再次安装以更新脚本。[Blender 5.2 启动脚本说明](https://docs.blender.org/manual/en/5.2/editors/preferences/file_paths.html#script-directories)

连接 Blender 后点击「卸载自动启动」可移除当前配置的 Qz 启动脚本。下次打开 Blender 时改为手动连接。若卡片提示启动目录动作未加载，先运行 **Reload Plug**，然后重试。

已经加载旧版 Blender 桥接时，保存场景并重启 Blender。在重启后的开发中台复制新的连接代码，再到 Blender 的 Python 控制台运行。用户脚本的导入、运行及管理见 [用户自定义脚本](user-scripts.md)。

原生回归使用独立的 Blender 5.2 界面进程、临时配置和随机端口。测试覆盖手动连接、版本、选择读取、脚本执行、繁忙状态和同端口重连。安装和卸载均使用同一隔离配置重启 Blender 验证。

```powershell
.venv/Scripts/python.exe -B tests/run_blender_native.py 'C:/path/to/blender.exe'
```

## 长任务期间的连接状态（协议3，2026-11-18）

Maya或Max执行耗时脚本时，主线程暂时无法处理请求并不代表桥接端口关闭。两端现在从socket线程回复桥接存活，再通过只读主线程探测报告是否能执行操作。Maya最多保留一个等待主线程的探测线程，Max最多保留一个等待worker的心跳任务；重复心跳复用待完成探测，默认只等0.2秒，不积压主线程请求。网络线程不调用Maya API或pymxs；版本由主线程查询并缓存。已知有中台任务执行中时报告“繁忙”，其他主线程阻塞报告“等待响应”。

中台状态分为已连接、繁忙、等待响应、持续无响应、桥接异常和未连接。一次心跳超时保留连接、版本和握手状态；连续3次无响应升级提示，但不据此声称端口关闭。已连接端连续2次被明确拒绝连接后显示未连接。用户主动断开成功立即更新状态，不等待这两次确认；过期回调仍受请求代次保护。繁忙/暂时等待恢复不重复握手、不弹重复连接成功提示，只有恢复响应时记一条日志。Max worker错误标记显示“桥接异常”及具体原因，即使端口仍可连接也不伪装成正常可用。

心跳/连接控制使用各端独立线程池，避免被中台的长插件任务占满全局线程池；原插件线程池的4线程上限保留。业务操作不因状态变化被取消、自动重发或改变执行超时。主线程已知长期等待时拒绝排入新的手动断开请求，提示恢复后重试；正常短暂心跳调度不妨碍断开。断开继续真正关闭端口，自动检测继续，未新增暂停自动重连开关。

本轮只更新开发源码，未构建或替换dist。需保存场景后重启对应Maya/Max及开发中台，使用同一开发目录生成的连接代码，加载协议3核心；只点Reload Plug不会更新已缓存的server模块。启动入口会拒绝已缓存的协议1/2核心并提示重启。旧打包版必须以后整体更新，单纯重启旧dist仍是旧核心。

## Maya 和 Max 的连接

未连接时两个状态行的按钮均显示“连接”。点击即复制对应软件的单行 Python 启动代码，并用短暂提示和日志确认；不发起连接请求、不等待、不弹启动代码窗口。用户将代码粘贴到 Maya 的 Python 输入区或 Max 的 Python 侦听器执行。后台自动检测独立继续运行，检测到可用桥接后握手、显示版本，并将按钮切换为“断开”。重复点击可重新复制代码。Max 显示「桥接异常」时，按钮为「重连」：点击复制当前运行版本对应的恢复代码，不请求故障 worker 断开。在 Max 的 Python 侦听器执行后重建 worker，等中台重新握手；旧任务不会自动重试。打包版使用 exe 旁的脚本。

两端代码均为一个物理行，可作为单条交互输入执行。Maya 使用 exec 包装必要的协议检查与异常提示；Max 使用分号连接语句，保留 Python2.7 文件路径编码处理及 runpy.run_path(..., run_name="__main__") 启动方式。路径统一为正斜杠并按 Python 字符串规则转义。

软件端同步绑定端口成功后才显示“桥接已就绪，等待中台确认连接”。中台通过 bridge_connect 握手后，两端给出一次“已连接”提示，中台同时记日志。Maya 使用视口提示，Max 使用 displayTempPrompt 状态栏提示，均不使用阻塞弹窗；重复心跳不会重复提示。Max 的 ping 在主线程读取 maxVersion 并上报 max_version，如2020；后台线程不调用 pymxs。

## Maya 和 Max 的断开

“断开”发送 bridge_disconnect，软件端停止监听并释放对应端口；Max 同时停用桥接定时器。收到停止确认后，中台将该端标记为未连接并给出反馈。不会调用永久关闭客户端的 close()，同一客户端可在软件端桥接再次启动后重用。Maya 和 Max 相互独立；自动检测继续运行，端口关闭期间无法连接，重新运行启动代码后可恢复。

正在执行中台任务时拒绝断开，完成后再操作。断开失败保留已连接状态并写日志，后续检测仍会反映实际状态。连接/断开与心跳使用请求代次，过期心跳不能将已断开的界面重新改回已连接；每端最多一个待返回的心跳，不累积请求。

监听 accept 设置短超时，保证 Python2.7 阻塞监听能及时退出并释放端口。Max 停止时设置 qzBridgeEnabled=false，定时器回调结束后据此决定是否恢复；重新启动先销毁旧 rollout，再定义和创建新实例，显式启用新定时器。

## 已运行旧版本时

连接控制初版为协议2；当前繁忙状态版本为协议3。已经打开的 Maya/Max 内缓存的旧 server 模块不会随动作库重载更新；首次使用新功能前应保存场景并重启相应软件一次。新版中台对旧核心仍采用保守等待策略，但完整独立心跳需协议3，不会假装旧核心已升级。

Max 自动启动生成代码也已改为 Python Execute + runpy，复用单行临时启动逻辑，避免 ExecuteFile 在 Python2.7 编译 Unicode 源码时拒绝编码声明。已安装旧自动启动脚本的用户，可在 Max 自动启动插件卡片重新点击“安装”更新标记块；其他自有脚本内容保留。仅将临时代码从多行改为单行不要求重新安装。

## 日志设置

日志行数上限通过 ui/layout_state.py 保存到用户 layout.json 的 log_max_lines，默认1000，范围100～100000。界面初始化和日志面板都读取保存值，修改即时保存，窗口关闭保存布局时保留。
