# Maya 蒙皮权重（第一版）

## 问题顶点选择、负权重修复与锤式修复（2026-11-18）

独立的空标题 QGroupBox 中，按钮依次为“选中问题顶点”“修复负权重顶点”“锤式修复问题顶点”。检测到负权重、全零、NaN 或 Infinity 后启用三个按钮。仅影响骨骼数量超限的合法顶点仍由原来的选择/修改按钮处理。

选择使用上一次检测保留的完整问题编号，不受当前选择变化或日志最多12个示例的限制。编号通过临时uint32文件传回Maya内存，之后释放稠密快照和交换目录。检测记录最多保留16份、30分钟；动作重载/重启后失效。模型通过UUID定位；删除替换、蒙皮替换、顶点数或连接拓扑变化时拒绝旧记录。

“修复负权重顶点”只处理检测记录中仍含有限负值且总和为正的顶点：负项置零，将负值总和平均扣减到原有正权重；小正值扣至零后，余量继续平均扣减给剩余正值。保留原始总和，不强制归一化到1、不按界面小数位量化，不新增原本为零的影响。无负值的正常点不修改；全零、NaN、Infinity、没有正值或总和不为正等无法保持总和的顶点跳过，明确计入未修复并提示重新检测后使用锤式修复。不按负值大小设置阈值，不自动调用锤式修复，不查邻近顶点，不改变选择。通过显式组件参数的原生 skinPercent 写入，整次多模型修复放在一个Undo块，可一次撤销/重做。写入期间临时关闭并恢复 influence liw、normalizeWeights、maintainMaxInfluences 及其属性锁；不改DQ。正常成功路径以原生命令返回为准，不重复读回。异常时报告已完成数和可能部分修改，不把失败命令记为成功。

“锤式修复问题顶点”保留原行为：对记录中仍异常的点调用 Maya weightHammerVerts，包括负值、全零和非有限数；已手工修好的点不再锤。使用相邻顶点权重及原生命令的锁定/归一化规则；只读回本次目标，报告实际修复、仍异常和未能确认的数量。恢复原选择，多模型一次Undo撤销。

任一修复后清除旧问题记录并提示重新检测；重新检测、修改超限或导入文件也会清除卡片旧记录。发送Max、导出和选择操作保留记录。任务期间三个按钮均禁用，完成后由检测记录决定可用状态。

验证：专项32项、权重文件/传输70项全部通过；独立Maya2024临时场景通过多模型数值修复、小正值扣尽后再分摊、总和非1保持、原零影响保持、正常顶点保持、稀疏influence编号、liw与设置/属性锁恢复、DQ保持、一次Undo/Redo、NaN/Infinity/全零/非正总和跳过；原锤式修复及一次Undo也回归通过。原生证据：`build/maya-native/negative_skin_native_fixture-8ec0f031/result.json`。Qt主题离屏预览确认三个按钮顺序及独立分组。未连接或操作用户场景，未打包、未改dist及共享桥接。源文件同步到主开发后，重启开发中台并在Maya分组执行Reload Plug，再重新检测使用。

## 原有检测与超限处理

选择一个或多个已有单层 skinCluster 的多边形网格，卡片提供检测最大影响数、选择超出顶点、修改超出影响。组件选择会解析到所属网格，操作范围为整个网格；不递归处理组选中的子物体，不支持多层蒙皮。新增底部“发送权重到 Max”按钮，单向同步到同机已连接的 Max；具体匹配规则及验证边界见 [Maya→Max权重传递](skin-transfer.md)。“发送权重到 Max”分组上方另有独立 QGroupBox，提供“导出权重”“导入权重”两个按钮；规则见下文。

最大影响数为可选正整数，默认 4。有效影响数按实际大于零的权重计数，不把修改时的小数精度误当作检查时的忽略阈值。全零、负值、NaN、Infinity 顶点跳过，日志记录各原因的总数及每个物体最多 12 个示例；最大影响数仅统计合法顶点。没有超限顶点时不改权重或当前选择。

按比例分配：保留最大的 K 项，按比例归一化。平均分配：先归一化原行，再将删除的余额平均加到保留项；并非将保留项设为等权。并列时优先 influenceObjects 顺序靠前的项。

计算使用 float64。只对合法且超限的顶点写回，未超限顶点不改精度。修改结果以 0.001 为单位（脚本 WEIGHT_DECIMALS 默认3），按最大小数余量补齐整数单位，使总和为 1000；舍入到零的项不计有效影响。不会创建、删除或重新绑定 skinCluster，也不修改 blendWeights、蒙皮算法、骨骼位置或名称。

所有 influence 都参与计算，不按 Maya 锁定标记跳过。写入期间临时关闭 influence 的 liw、normalizeWeights 和 maintainMaxInfluences，并恢复其值及属性锁定状态；无法修改必要设置时报告失败。直接 API 写入不承诺原生撤销；失败恢复使用操作前快照。正常模式以 Maya 写入接口成功返回为准，默认不读回复查；开发调试时可开启逐批复查。写入或调试复查报错时，恢复当前物体的已尝试批次，并确认恢复结果，其他物体独立处理。若恢复也失败，日志明确提示检查场景。

中台后台任务：发起 Maya 快照 → NumPy 计算 → Maya 应用/选择 → 释放任务。Maya API 均由 bridge 调度到 Maya 主线程。操作固定为开始采集时选中的模型，Maya 保留其 API 句柄；不再比较 UUID、拓扑、influence 或全量旧权重，允许直接用读取快照的计算结果覆盖期间的权重变化。写前只确认接口所需的尺寸、数量及编号范围，归一化和配置的小数精度由中台整数余量算法生成保证；正常模式关闭写后复查，失败恢复仍保留；调试开关可开启复查。统计基于本次快照。中台等待时卡片输入和按钮禁用，界面保持响应。网络超时不代表 Maya 已取消，不自动重试写操作。

数据交换使用本机系统临时目录 qz-skin-*，JSON 仅传任务标识、尺寸和统计。输入为按块读取的 little-endian float64 **稠密**权重文件（保留零项），不使用 zip/zlib，不等同于参考中的去零稀疏压缩。输出只包含超限顶点：uint32 顶点 ID、uint32[M,K] influence 列号、float64[M,K] 权重；K 个槽位中允许舍入后的零项。Maya 按有界块展开后批量写回。默认每块至多 2048 个顶点或 262144 个权重元素。任务临时文件完成后清理，Maya 端任务元数据 30 分钟过期。断连时可能残留临时目录，可在确认 Maya 没有运行任务后清理。

NumPy 2.3.5 为中台运行依赖，安装在项目 .venv，并随 PyInstaller 产物收集；Maya 不安装、不导入 NumPy。外置插件所需 ui.skin_weights 必须列入 hidden-import，发行自检需实际 import NumPy 并执行一个数组运算。UI 不与 Max 共用，按钮不加 tooltip，卡片宽度按内容自适应，详细结果仅进日志。

离线验证覆盖 NumPy 实际计算、五位舍入、异常、二进制传输、Maya API 替身读写、快照覆盖/固定目标、失败恢复、真实 Qt 点击与后台回调。Maya 实机操作与大模型性能需在 Maya 中验证，离线替身不代替实机结论。

## 中文日志和内部计时

三个操作都先输出中文摘要（模型数、扫描顶点数、超限/选中/修改数、异常数、最大有效影响数），再输出异常分类、顶点示例和对象失败原因。部分失败不显示预计成功的最大影响数，明确提示重新检测；异常走警告、失败原因走错误，所有日志在中台 UI 线程写入。既有插件日志行为不变。

用户日志只显示操作结果、异常原因及总耗时，不输出分阶段调试耗时。详细计时仅保留在内部响应供开发诊断。计时使用 perf_counter，只交换已测得的时间长度，不相减两个进程的时钟值；总耗时含释放任务及临时目录清理。

Maya 采集包含网格/蒙皮准备及 API 读取，不计算拓扑摘要。Maya 编码单独记录数组转换为 little-endian float64 字节的耗时；Maya 写文件记录快照文件打开、写入与关闭（含缓冲刷新）；中台读文件记录输入文件尺寸读取、打开、np.fromfile 与关闭；中台写结果记录补丁文件打开、tofile 与关闭。文件计时是写入操作系统缓存的耗时，不执行 fsync，不能视为物理磁盘持久化耗时。Maya 数据匹配仅含最小接口参数匹配，写回、复查和失败恢复各自包含该阶段内部的补丁/原快照读取和数据展开，避免重复累计。NumPy 处理扣除显式文件读写计时，包含数值统计、筛选、五位舍入和结果整理。桥接/排队是中台等待耗时减去 Maya 自报动作执行时长的余额，包含请求序列化、排队和响应等，不能当作纯 socket 传输时间。

Maya 还未重载新版动作库时仍可操作；内部计时将未分段耗时单独记录，不伪装成已取得细分计时。旧版阶段字段同样不会出现在用户日志中。

## Maya 编码优化验证（2026-11-05）

Maya 端直接用标准库 struct.pack 将每批 MDoubleArray 打包成 little-endian float64，替代 array("d", weights).tobytes()。不需要在 Maya 安装 NumPy，不读取原始内存指针，也不是零拷贝；临时参数序列随当前批次释放，文件格式和数值精度不变。Maya API 2.0 的本机 MDoubleArray 不支持 memoryview，不能假设可直接传给 file.write。最后一次 tobytes 复制在262144元素基准中仅约0.4ms，主要收益来自替换原数组转换路径。

在用户已运行的 Maya 2024 / Python 3.10.8 中验证真实 MDoubleArray，四种块大小（384、6144、32768、262144元素）各轮换21次，实际写临时文件并逐字节比对。262144元素中位数：原编码13.6923ms，直接struct打包6.1867ms；包含写入/flush的合计14.0141ms → 6.4848ms。普通值及负零、最小非零double、最大有限数、负值、±Infinity、含负载NaN、空数组，均保持原float64二进制位。全块和尾块的离线文件传输回归也通过。

同一49566顶点模型交替运行原编码/新编码各6轮只读检测，各排除首轮后取中位数：Maya编码321.927ms → 151.041ms，降低53.1%；检测总耗时0.534650s → 0.352866s，降低34.0%。各轮模型、顶点、异常、最大影响数报告一致，期间未选择或修改场景权重。单次耗时会受系统负载影响；实际修改操作的端到端收益未在本轮实测。原始记录位于build/skin-encoding-probe.json、skin-encoding-refined.json、skin-encoding-live-comparison.json、skin-encoding-final-verification.json，均为开发测试产物。

用户确认后续所有测试仅在开发目录执行，不再打包测试。当前修改已在开发目录验证并重载Maya动作库，临时性能测试动作及文件已移除；发行目录未改动。


## 正常使用与开发复查（2026-11-05）

用户确认正常使用不需要重复读回已写入的权重。maya_actions/skin_weights.py 的 VERIFY_AFTER_WRITE 默认为 False；正常成功路径只读初始快照，写入后恢复临时设置即结束，不再次展开补丁或读取 Maya 权重，也不输出“Maya写后复查”计时。正常模式无法发现未抛异常的写入结果偏差，结果统计仍以快照计算和 Maya 写入接口成功返回为准。

开发者需要逐项确认写入结果时，可在 Maya Python 中将 maya_actions.skin_weights.VERIFY_AFTER_WRITE 设为 True；重载动作库会恢复默认 False。此开关仅供开发调试，没有增加卡片控件或改变桥接参数。开启时只复查本次修改的顶点，失败时仍按原流程恢复。

写入异常、补丁应用异常或设置恢复异常仍会触发恢复。异常恢复路径保留恢复后的权重确认，便于准确报告“已恢复”或“恢复未完成”；这一步仅在发生异常时执行，不影响正常成功路径。检测、选择、五位精度、异常报告及忽略 influence 锁定的计算策略不变。

用户实机基线写后复查132.648ms，按其修改总耗时0.716s估算，关闭后约0.583s；这是同等条件下的估算，并非本轮场景写入实测。验证仅在开发目录执行，不打包；测试覆盖正常成功写入不重读/不输出复查计时、调试开启后只读修改顶点、调试不一致和部分写入失败的恢复。


## 项目内权重导入导出（2026-11-06）

目录固定为中台项目根目录下的 `temp/skin_weights/`，由统一入口 `paths.project_dir()` 获取（开发模式为中台源码根目录，发行运行时为 exe 所在目录）；不读取 Maya 项目或场景目录，不增加项目、场景标识或 qz 子目录，不弹路径选择窗口。每个选中模型单独保存 `模型名.qzskin`，再次导出同名模型覆盖对应文件；未选中的其他文件保留。退出中台和重启不清理文件。日志显示实际目录、成功数、失败原因及总耗时。普通模型名直接作为文件名；命名空间冒号等 Windows 禁用字符采用百分号编码，中文保留。文件名冲突（含大小写冲突）跳过并报告。

导出支持一个或多个已有单层 skinCluster 的选中网格。复用 Maya 完整权重和 blendWeights 采集，中台 NumPy 转为稀疏数据。全零、负值、非有限权重、非法 DQ 或有权重骨骼重名时，跳过整个模型，保留旧文件；其他模型独立处理。新文件在目标目录暂存，完成后替换，打包或写入失败不覆盖上一次成功数据。没有内存复制/粘贴功能，没有自动历史版本。

`.qzskin` 为 ZIP 容器（低级别无损压缩），包含 `manifest.json`、`offsets.bin`、`indices.bin`、`weights.bin`、`dq.bin`；版本3另含 `points.bin` 和 `triangles.bin`。描述格式 `qz.skin_weights`、当前版本 3（仍可按编号读取版本1/2），记录原始模型名、顶点数、原 influence 列数、非零权重数、实际有权重的骨骼原名及列编号、UTC 导出时间，以及 `skinning_method`（0=线性，1=双四元数，2=混合）。二进制按 little-endian uint32 CSR 行偏移/列编号、float64 权重和每顶点 float64 DQ 保存。保留原始有效权重数值，不执行量化、裁剪、额外归一化，不应用界面最大影响数或分配方式。

导入只处理操作开始时选中的模型，按其原始名称查找文件；文件名、文件内名称及顶点数必须匹配。中台先检查版本、数据长度、CSR 索引、非负有限权重和 DQ 范围，再把通过检查的模型交给 Maya。实际使用的骨骼必须在场景中唯一存在；只兼容 `FBXASC032` 空格编码，不去命名空间，不模糊匹配。缺骨骼、多层 skinCluster 或匹配失败时跳过并报告。未使用的 influence 不要求存在。

无 skinCluster 时自动绑定到已存在的所需骨骼；已有 skinCluster 缺少 influence 时添加。按目标 influenceObjects 顺序重新映射，覆盖整个网格的权重与 DQ，包括清零目标多余影响。顶点编号和初始姿态由制作流程保证，不保存几何、拓扑对应和骨骼姿态；导入成功后将 skinningMethod 恢复为文件记录值，让混合 DQ 数据实际参与变形。方式属性锁定时暂时解锁、设置后恢复属性锁。写入期间忽略并临时关闭锁定及自动约束，随后恢复值和属性锁定状态；新建绑定之前同样临时解除骨骼 liw 属性锁。按顶点编号导入保持原选择；最近表面点导入成功后自动选择插值顶点并保存选择集，见下文。

正常导入不读回复查，不增加 Undo 命令或完整旧权重备份。新建蒙皮导入失败会移除本次新建的 skinCluster；已有蒙皮写入中途失败时，明确报告可能部分更新，不声称已恢复旧权重。导出保留原检测结果，导入后提示重新检测。所有耗时工作使用现有后台任务，日志在 UI 线程输出，任务期间禁用卡片全部操作。

开发验证：新增文件/动作/Qt 交互测试覆盖完整精度/DQ、覆盖失败保留旧文件、多模型部分成功、文件损坏、缺骨骼、新建蒙皮、influence 重排与添加、多批次及最后不足一批、锁定恢复和 UI 分组顺序。真实已连接 Maya 2024 临时 4 顶点/3 骨骼模型通过完整往返、补加影响和删除蒙皮后重新导入；逐顶点读回权重/DQ，确认原骨骼锁定恢复。测试节点删除，原选择、撤销状态和场景修改标记恢复，文件只写开发测试目录。正常模式不进行这些读回复查。原始验证记录 `build/skin-weight-files-native-result.json`。仅开发目录验证，未执行打包。
